Code quality is high and consistent. Every reviewer independently scored quality 7–8. The recurring reasons: opaque builder types, labelled arguments, module docs that explain why, careful security reasoning (auth, static serving, CSRF, SAML), parameterised SQL everywhere, few let assert/panic in library code (mostly startup-time config validation), and tests that exercise real behaviour (real databases, real sockets on port 0, fuzzing, race tests, isolated-VM lifecycle tests).
Maintainability is the weaker axis, driven by a handful of very large modules. auth/src/howdy/auth.gleam is 4,427 lines with 206 functions and a 23-positional-field constructor. ui/src/howdy/ui/behaviour.gleam holds ~1,100 lines of JavaScript in a Gleam string with no lint or CI. Four admin page modules and flags.gleam are each ~1k lines mixing handlers, views and domain logic. Small helpers (getenv, describe, when, duration, host heuristics, URL credential parsing) are copied across packages. Telemetry couples to private OpenTelemetry SDK internals.
OTP is used fluently at the primitive level but fought at the application level. ETS compare-and-swap, pg, monitors, proc_lib, try/after bracketing, dirty-scheduler NIF: all good. But only howdy_ui and howdy_telemetry are real OTP applications. The framework, auth, database, flags, mail, remote and admin all rely on the caller's main process as the de-facto root supervisor, held alive by process.sleep_forever(). There is no howdy.supervised, no howdy.stop, no graceful drain on SIGTERM, and nothing restarts. Long-lived processes are either linked to main (a crash ends the VM) or are lazily-started unlinked singletons (crash means silent loss of state). ETS tables are owned by "whoever called new()".

Update after the second pass: howdy.supervised, howdy.stop and howdy.start_application now exist, every example runs its tree as an OTP application, SIGTERM drain is verified against a live VM, the database lock server is a supervised gen_server under a howdy_database application, the session store and flags keeper have supervised owners, and the rate-limit janitor can no longer take main down. After the third pass the medium items are closed too: both pg scopes are supervised under package applications, the telemetry recorder and auth caches have gen_server owners, the pool and outbox have child specs, admin timers use send_after, and the auth cache no longer touches the lock server.

1a. Resolution log: the 12 high findings

Each item names the finding, what changed, and how it was verified. All package suites and all nine example suites pass after these changes. Nothing is committed yet.

  1. Core: main was the supervisor. fixed
    Added howdy.supervised(app) (a child specification wrapping the server), howdy.stop(pid) (unlinks, sends shutdown, waits for the DOWN) and howdy.shutdown_timeout. All nine examples now build a static_supervisor tree; the admin example adds the flags keeper and the remote example adds the procedure directory as siblings of the server. Verified by test/howdy/supervised_test.gleam: a killed server is restarted under a new pid, and stop delivers a 1001 close frame to an open WebSocket before the port is freed.
  2. Core: no graceful shutdown path. fixed
    Added howdy.start_application(tree, name:) and stop_application, backed by src/howdy_application.erl, which loads a runtime application spec whose mod starts the tree. Because the tree belongs to an application, init:stop stops it in order. Verified end to end: ran the chat example, held a WebSocket open, sent SIGTERM to the VM, and observed CLOSE FRAME code=1001, socket closed, VM exited. New guide: docs/guides/supervision.djot, registered in docs/index.json and linked from the README.
  3. Database: unsupervised lock server with busy-wait. fixed
    howdy_database is now an OTP application (howdy_database_app.erl) whose supervisor eagerly starts howdy_database_locks.erl, a gen_server registered under the same name. Fair FIFO, reentrancy and release-on-death are preserved; the register race and after 1 polling are gone. On a restart, waiters exit with {howdy_database_locks_lost, …} rather than being granted a lock beside a still-running holder. Tests: 35 passed in database, 264 in auth (the main caller of with_lock).
  4. Core: rate-limit janitor could take main down. fixed
    The janitor now creates and owns the ETS table, is not linked to the creator, monitors it and deletes the table when it exits (same lifetime as before), and catches sweep errors with a logger:warning instead of re-raising through a link. The owner_lifecycle test was updated to find the janitor via ets:info(T, owner) and asserts the creator has no links.
  5. Flags: keeper crash froze settings forever. fixed
    Added flags.supervised(config) -> #(Flags, ChildSpecification). The handle now holds a fixed persistent_term key and a process.Name chosen before the keeper starts, so a restarted keeper re-publishes under the same key and the same handle keeps working. Exits are trapped and withdraw the key; current/1 uses a default so checks fall back to the flag's declared default instead of raising badarg; store calls are guarded so a raising store logs and keeps the last snapshot. Four new tests including kill-and-restart under a supervisor; 32 passed.
  6. Auth: memory session store crashed every request after owner exit. fixed
    New howdy_auth_sessions.erl gen_server owns the table and publishes ref → tid in persistent_term; every sessions_* op catches badarg and maps to Error(service.Internal(…)). session_store.memory() starts an unlinked owner; new memory_supervised() returns a child spec plus the store. Three new tests: outlives creator, deleted table fails closed, supervised restart; 264 passed.
  7. Admin: host check did not stop cross-site POSTs. fixed
    only_hosts now rejects POST/PUT/PATCH/DELETE unless Sec-Fetch-Site is same-origin/none, or (with no fetch metadata) a single Origin whose authority equals the request authority and whose host is allowed. GET/HEAD/OPTIONS unaffected, so the live grid's WebSocket upgrade still works. README and docs/admin/overview.djot no longer describe CSRF as an accepted limitation. Five-case test; 46 passed.
  8. Database: reverse-nested transactions used two connections. fixed
    postgres.transaction checks the process-dictionary depth key via database.in_transaction() and returns Error(service.Internal("a pool transaction cannot be opened inside a repo transaction")) before touching the pool. Documented; tested without Postgres using an in-memory SQLite outer transaction and a never-connected pool.
  9. UI: 1,100 lines of JavaScript in a Gleam string. fixed
    Moved verbatim to ui/priv/behaviour.js, loaded once from code:priv_dir(howdy_ui) and cached in persistent_term; behaviour.script() unchanged. New test runs node --check on the file when node is present. The CDP browser suite now runs in the ui CI job against the gallery (32 browser tests passed locally). 138 passed.
  10. Release tooling omitted openapi and flags. fixed
    Both added to dev/howdy_release.gleam and scripts/release.sh (eleven packages enumerated). docs/openapi/overview.djot now says to depend on the v2 branch until the next tag. Dry-run howdy_release check resolves all eleven; releases/ left untouched per RELEASING.md.
  11. CI never tested openapi, telemetry, or two examples. fixed
    New openapi and telemetry jobs; example matrix now includes openapi and gallery; README claim corrected and dead benchmark links removed; namespace guard extended to openapi/telemetry/ui/dev. Workflow YAML validated; all newly covered suites pass locally.
  12. Core: global logger filter matched on a dependency's wording. fixed
    The crash-report branch now also requires the exit to have been raised from tup_ffi:exit_with (a structural check on the stack), so a handler that exits with the same words is still reported. Added howdy.log_disconnects(app) to opt out. The einval phrase stays because it is the observed reload case. The guarding disconnect_log_test still passes.
Test totals after the pass. Core 259 · auth 264 · ui 138 · admin 46 · flags 32 · database 35 · remote 30 · mail 42 · telemetry 15 · openapi 23 · howdy_dev 11 · examples 70 across nine suites. Zero failures. Formatting checked in every package.

Verdict

The low-level BEAM craftsmanship is genuinely good: lock-free ETS compare-and-swap rate limiting, pg for pub/sub and service discovery, monitors wherever one process depends on another, proc_lib with init_ack, a precise primary logger filter, a dirty-scheduler Argon2 NIF, and try/after bracketing for locks, transactions and spans. The per-request hot path touches no singleton process: routing is a pure table, rate limiting is ETS CAS, flag checks are persistent_term reads, session lookups are ETS, and ewe rescues handler crashes into a 500.

What is missing is the application layer. Every long-lived process outside howdy_ui is either linked to main (so a crash halts the VM under gleam run) or is an unlinked, lazily created, registered singleton that nothing restarts. There is no howdy.supervised, no howdy.stop, and no application start module in the framework or the examples. ewe's own documentation says draining connections on shutdown only happens inside an OTP application's supervision tree, which howdy's API cannot reach. The codebase uses BEAM primitives fluently but fights OTP structurally.

Done well

  • Per-request hot path has no singleton bottleneck.
  • Rate limiter lifecycle is textbook: linked janitor monitors owner, stops when the table vanishes, proven under a barrier-released parallel test.
  • pg used correctly for WebSocket topics and RPC discovery; dead sockets leave for free.
  • Remote: handlers never run inside the directory; erpc per call with timeouts; every failure class mapped to a typed error; the pg sync race is handled and tested with real peer nodes.
  • Bracketing is crash-safe: with_lock, transactions, spans all use try/after; a panic inside a transaction rolls back, ends the span and clears the depth key.
  • howdy_ui is a proper application with lazy ensure_all_started fallback and isolated-VM lifecycle tests.
  • Telemetry boots the SDK carefully: no-op until opt-in, parent-based sampler, resource merge.
  • Argon2 NIF is ERL_NIF_DIRTY_JOB_CPU_BOUND.

5. Cross-cutting themes

These patterns showed up in three or more independent reviews, so they are properties of the codebase rather than of one package.

Structural

  • No supervised entry points. Postgres pool, flags keeper, mail outbox, telemetry recorder, session store and the server itself all only offer start. Only remote.supervised exists. This is the single biggest OTP gap and it is cheap to fix per package.
  • ETS owned by the caller. Auth (4 kinds), rate limiter, telemetry. The docs say "construct once from a long-lived process", but nothing enforces it and a request-process creator takes the table with it.
  • Lazily created global singletons (lock server, pg scopes) that nothing restarts.
  • God modules: auth.gleam (4.4k), flags.gleam, four admin page modules, ui/cli.gleam, openapi/endpoint.render (225 lines in one function).

Duplication

  • getenv/1 in database, telemetry and mail FFI; loopback/dotless host heuristic in postgres and smtp; URL credential decoding in both from_urls; present/3 in resend and sendgrid. A shared howdy/env and howdy/url in core would remove ~80 lines.
  • Admin: describe ×3, when ×4, duration and now() re-derived in three flags modules.
  • UI: focus ring ×40, border ×61, radius ×79, disabled ×12 copies of the same style fragments; per-instance <style> for keyframes.
  • Identical to_dynamic/from_dynamic externals in two openapi modules.

Tests

  • Sleep-based synchronisation in core, auth (up to 60 s to align with a minute boundary), admin, remote, mail, telemetry tests. The rate-limit tests already show the right pattern: deadline polling.
  • Coverage is uneven. Auth and core are well covered (0.67–0.85). UI is 0.13 with 13 components untested beyond "the gallery serves it". Admin is 0.21. OpenAPI's three documented panics and ~10 public functions are untested.
  • Telemetry tests mutate global SDK state and env vars, so they are order-dependent within the file.
  • The UI browser suite exists but does not run in CI.

Error handling

  • Library let assert/panic counts are low and mostly build-time, which is the right policy. Exceptions worth fixing: request-time URL builds in auth providers, telemetry.gleam:450 in admin, chart.gleam:213 on non-finite floats, cookie name validation per request.
  • Several decoders map failure to None and silently continue, most seriously turning flags.undo into a delete on a corrupt before value.
  • process.call/actor.call timeouts crash the caller (flags memory store, outbox) instead of returning Unavailable.

Security posture

  • Strong overall. Notable gaps: admin host allowlist does not block cross-site POSTs; SSRF guard is resolve-then-connect; impersonation tokens cached in persistent_term forever; crash reports (which can carry secrets) exported as span attributes; UI inline handlers and styles block a strict CSP; UI CLI accepts http:// registries.

howdy_auth Q 8 · M 6 · OTP 6 · 1 high, 6 medium, 9 low

Pure library, no processes of its own. 55 src files, 16.4k lines Gleam, 8 FFI modules plus a vendored Argon2 NIF. 261 test functions, every one against a real database (SQLite in-memory per case, Postgres via env).

Strengths
