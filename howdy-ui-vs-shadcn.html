“Missing” means not supplied by howdy_ui. Lustre, native HTML, custom Sketch classes or application code can implement these interfaces. That does not provide a ready-made, themed, reusable howdy component.

Howdy already provides

Native buttons, inputs and labels; headings and text; container, card, stack and row; light/dark and custom themes; a theme toggle; editable component copies and diffs; deterministic static CSS export.

It also provides page rendering, WebSocket-backed Lustre server components, shared runtimes, live navigation and shadow-root styling.

Package README · Public API

The architectural difference

Howdy combines UI helpers with a Gleam/Erlang server integration. Shadcn distributes editable UI source and React-oriented behavior, with a larger component and registry ecosystem.

React, Tailwind or Radix compatibility is not automatically a requirement for Howdy. The useful target is equivalent user-facing behavior through Lustre and Sketch.

Suggested implementation order

This is an engineering recommendation based on reuse and dependency order, not a measured estimate of effort.

01Complete everyday building blocks

Extend button sizes/variants, card parts and input states. Add Field, Textarea, Native Select, Checkbox, Radio Group, Badge, Alert, Separator, Table, Skeleton and Spinner.

Result: practical forms and ordinary application screens with much less application-specific styling.

02Build shared browser behavior

Choose how focus, dismissal, popup positioning, ARIA relationships and keyboard navigation work with Lustre live patches and shadow roots. Use that foundation for Dialog, Popover, menus, Tooltip, Select, Tabs and Accordion.

Result: related widgets share a coherent interaction implementation. Verify keyboard and screen-reader behavior as these are added.

03Compose application features

Add Toast, Sidebar, Pagination, Calendar/Date Picker, Combobox/Command, Data Table and Chart. Build a few reusable forms, authentication screens and dashboard blocks.

Result: higher-level interfaces become compositions of existing parts. Decide where browser-local state is needed to avoid server round trips for immediate interactions.

04Expand distribution and specialist UI

Add a component gallery, dependency-aware installation and registry manifests. Extend theme roles with the catalog. Prioritize chat components, Questionnaire, advanced media, design resources and agent tooling according to real demand.

Result: a larger library becomes easier to discover, maintain and share.
